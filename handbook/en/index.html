Getting started · Free + Pro

First setup: from offer to enquiry

A complete first-installation workflow using a simple fictional studio service.

Where to find this setting

WordPress → Plugins; then OfferWeave → Offers / Settings

Settings: General and labels

Open Settings → General and labels. Brand, introduction, selection page and quantity/option labels.

What OfferWeave does

OfferWeave presents your services as offer cards, calculates a selection and saves the enquiry with contact details and a snapshot of its prices. Customers can collect services across several pages. Depending on your settings, a price summary or an offer is then emailed to the customer.

The plugin has no payment checkout, invoice creation or appointment calendar. A selection does not reserve a date or capacity. All examples in this handbook are fictional; enter all prices as net amounts.

Prepare the installation

  1. Use WordPress 6.5 or later and PHP 8.1 or later. Back up the WordPress database and plugin directory before an update.
  2. Go to Plugins → Add Plugin → Upload Plugin. Select the ZIP for your edition, then install or replace the existing version.
  3. Activate OfferWeave. Free starts without sample offers. A WordPress administrator account is required to configure it.
  4. Open OfferWeave. Tabs at the top lead to offers, form fields, settings and other areas. Draft changes take effect only after using the shared save button.

Create your first service

  1. Open Offers → Add offer. Use “Layout design” as the name and layout as the unique ID. Set category ID studio and category label “Studio services”.
  2. Choose “Fixed price × quantity”. Enter €120.00 as the net price per unit. Describe what is included, for example “Design of one print layout; one revision included”.
  3. Enable both “Enable offer” and “List individually in the catalog”. Save.
  4. Open Settings. Add the recipient, provider details, customer audience and your privacy notice URL. Review the tax settings explicitly.

Test page and first enquiry

  1. Create a WordPress staging page and add a Shortcode block containing [offerweave]. This places the catalogue, selection and enquiry form together.
  2. Visit the page, select Layout design and enter quantity 2. Check the €240.00 net result. With 19% VAT enabled, the gross result is €285.60.
  3. Submit an enquiry with your own test details. Check that it appears under OfferWeave → Requests.
  4. Check actual email arrival. New installations do not automatically email the customer. Choose a customer email mode explicitly under Email.
  5. Publish on your intended pages after a successful test. For separate catalogue and request pages, follow “Pages and shortcodes”.

Using this handbook

Search includes chapter contents. Each chapter shows the menu path for its settings. “Free + Pro” means the feature is shared; “Pro” identifies additional features. Images show the real interface using fictional data. Labels can differ with the WordPress language.

The same chapters are available under OfferWeave → Documentation in WordPress. The bundled handbook does not load an external website. Use Print to save the current chapter or the complete handbook as a PDF.

Build your catalogue · Free + Pro

Offers, categories and detail pages

The basic card fields and the difference between enabled and individually visible.

Where to find this setting

OfferWeave → Offers → choose an offer → four areas

Find an offer

Search, role, status and category filters stay at the top of the offer sidebar. Only the matching offer entries below them scroll. The result count, Reset filters and Add offer remain outside the result list. Switching offers preserves filters, the open draft and list position. Changing a filter starts at the top of the results. An open draft stays open even when it no longer matches the filter.

Scroll the results with the mouse wheel or touch. Tab reaches the result region and its offer buttons; Page Up/Down scrolls the focused list. On narrow or short screens the sidebar stays in the normal page flow while the results still scroll independently.

Four areas instead of one long form

  1. Content and appearance: name, description, card text, price unit and image.
  2. Price and quantity: pricing model, price, quantity rules, unit labels and draft preview.
  3. Packages and options: included content, separate component prices for assembled packages, variants and travel costs.
  4. Publication: unique ID, category, visibility, detail address and shortcodes.

Key facts with your own icons

Under Offers → Content and appearance → Key facts, add up to four entries with your own image files. Each row has a text field, a small image preview and “Choose / upload”. There is no predefined icon list. New rows start without an icon and display only the text. Also available in Free.

Key facts automatically spread across the available inner card width. Each icon and label remain one group. Existing padding and minimum gaps are preserved. When space is limited, whole groups move to a new line; long text can wrap within its group. A single item stays left-aligned. This applies to all card layouts and the preview without an extra setting.

  1. Click “Add key fact” and enter text. Each row allows up to 480 characters; short facts are easier to read.
  2. “Choose / upload” opens the WordPress media library. Use “Upload files” to add your own image or “Media Library” to select an existing image. Confirm with “Use this icon”.
  3. The small × directly above the icon preview clears only the image assignment (tooltip “Remove icon”). The file stays in the media library. The arrows on the right move text, icon and translations together; the right-hand × beside the arrows removes the entire key fact.
  4. Save to publish changes. The same own icons appear in all card layouts and the designer preview. Duplicating an offer keeps its assignments.

Use small, preferably square PNG, WebP, JPEG, GIF or AVIF files; transparent PNGs work well for isolated icons. Display preserves their proportions. SVGs from the media library are also supported; new SVG uploads must be enabled in WordPress. Icons next to their text are treated as decorative for screen readers.

Export/import keeps image addresses, not image files or media IDs from another installation. Icons remain visible while their original addresses are reachable. For a complete move, transfer the files to the target site’s media library and assign them there. A missing image can be selected again or removed.

Version 2.16.1 removes the previous predefined key-fact symbols. Text and order remain intact; select your own image files for any desired icons. Other card symbols are unchanged.

Create and save

Add offer provides starting points. A single offer starts with fixed price × quantity; the two package presets are available in Pro. Then adjust the existing rules. Cancel creates nothing. Switching areas never saves: use the save button to apply your configuration.

The role describes composition. The pricing model describes how the price is calculated. A module is not a separate offer type. An included single offer keeps its own calculation.

Catalog and detail page

Under Publication enable the catalog card and add a detail URL if needed. Place [offerweave_add id="layout"] on the detail page. IDs do not depend on list order. Use [offerweave_catalog category="studio"] for a catalog and [offerweave_selection] separately for the selection.

Yellow notice for mixed categories

A category can still contain different calculation models. A yellow notice appears at the top of the offer editor when active offers with their own catalog cards use different models. It does not prevent saving or change prices.

Open “Review offers and price rules”. Each model lists its affected offers. Click an offer to open its price rule directly. Inactive offers and components without their own catalog cards are excluded. The notice already responds to changes in the draft.

For a consistent shared quantity, use suitable matching models within a category. Delivery format is shared even with mixed models. Review each offer under Price and quantity and configure its own group size or tiers. Categories do not share a price rule: changing a model never automatically changes other offers or package components.

Alternatively, choose “Independently on each offer card” under Settings → General and labels. Each card then owns its quantity and delivery choices and the shared block disappears, even with identical pricing models.

Notices and confirmations

OfferWeave displays its notices and confirmations in its own dialog windows. Read a notice and dismiss it with Understood, the close button or Escape. Cancel, close or Escape leave a confirmation without making a change. Only the labelled action button performs the action.

If a package has assigned components, explicitly remove those assignments under Packages and options before changing to a price model without components. Closing the notice does not remove any assignments.

Reloading, closing or leaving a page with unsaved changes can still show a browser warning. The browser controls its wording and appearance. This protection against data loss remains in place.

Resolve a missing selection package in Pro

An older saved assignment may refer to a selection package that no longer exists. Pro displays its ID under Offers → select the offer → Price and quantity → Calculation and input. Displaying the notice does not change any data.

  1. Check the displayed package ID and this offer’s own prices, group sizes and options.
  2. Click Configure independently if the offer should use its existing settings. Only the reference to the missing package is removed; prices and variants are preserved.
  3. Check the price calculation and click Save changes. Any remaining invalid assignments are still reported when saving.
Normal editing of Free offers remains available in Free; saved Pro data is preserved. Switching editions does not silently remove a missing Pro assignment. You can explicitly correct it when you next use Pro.

Calculate prices · Pro

Calculation models and tiered pricing

Choose the right model and verify its formula with concrete numbers. Fixed prices are also available in Free.

Where to find this setting

OfferWeave → Offers → Price and quantity

Choose the model

Fixed price × quantity multiplies the base price by the number of units. Group calculation divides the total input quantity by group size and rounds up. Tiered pricing selects the base price for the quantity and charges additional units within the configured bands. Assembled packages add only their own stored component prices, then apply the package quantity or group basis.

Set up tiers

Limits must increase across tiers and surcharge bands. Print example: up to 100 copies costs €600; up to 200 each additional copy costs €3. Thus 150 copies cost €750 net. Monthly offers use monthly amounts. Above the automatic calculation limit the price remains open.

Calculate the draft

  1. Go to Test the calculation under Price and quantity. It uses your unsaved settings.
  2. Choose quantity and, where applicable, contents, variants and travel inputs. Calculate draft uses the same calculation as the customer area.
  3. Test a normal quantity, the last quantity in a group/tier and the first above it. With 20 units per group, 21 units produce two groups.
  4. Review net, tax, gross, terms and outstanding costs. Eligibility messages concern this item; further items may make the request eligible.
Preview creates no request and sends no email. Changing an input clears the stale result. Invalid configurations must be corrected before calculation.

Quantities in matching and mixed categories

When all visible offers use the same calculation model, the shared quantity remains above the cards. When fixed price times quantity, group conversion or tiered pricing are mixed, every card has its own quantity before its price. Delivery format remains a shared selector above the cards. It applies to all offers with a delivery rule; quantities stay independent. Additional custom variants remain inside their respective card.

Example: a studio session costs €200 per group of up to 10 guests, with no discount for further groups. Enter 30 guests in its card: the price is €600. A layout service costing €120 per template starts at quantity 1. Set its card quantity to 2: it costs €240 while the studio session stays at €600.

Fixed-price cards start at quantity 1. Group and tiered offers use their own default quantity and input unit. An invalid card quantity blocks only that offer. Adding it preserves its quantity, options and any travel details. Package and component rules stay independent. The yellow notice remains only in the administrator’s Offers area.

A shared “On site” choice uses each offer’s own surcharges and variants. If an offer has several variants for the same format, choose its additional delivery variant on that card. Unavailable offers cannot be added for that format. Travel details stay on each card; changing the shared format later does not alter items already added to the selection.

Contract terms, totals and custom price notes

For monthly offers, open Offers → Price and quantity → Billing. Turn off “Show total cost for the contract term” to keep only the monthly price and contract term on the card. This applies to category and single cards, the design preview and [offerweave_add]. Available in Free and Pro.

The automatic term text comes from the contract duration. Replace it using “Contract term text”, for example “Minimum term: {months} months”. {months} inserts the current duration automatically. Leave the field empty to restore the default text.

The term total combines the calculated monthly amount multiplied by the contract duration with the default suffix “for the entire term”. Customize the suffix using “Text after the term total”. The amount is still calculated and updates with quantities, options and promotions. Hiding the total or switching to one-time billing preserves your texts.

Other accompanying text comes from Offers → Content and appearance → Additional price note. Edit or remove your note about a one-time project there. An empty field shows no additional note.

These settings affect the display before selection. Contract duration, calculation, the complete request summary and emails stay unchanged. The tax label remains immediately below the price. Custom texts are available in the existing translation editor.

Explain quantities, groups and price units

Convert a total quantity into groups and show the rule clearly on every card.

Where to find this setting

OfferWeave → Offers → Price and quantity → Groups / Unit labels

Separate input and billing

The customer enters the total quantity, such as 25 people. With 20 people per group, the offer calculates two groups. The price unit on the card is only a label; it does not enable group calculation.

Configure groups

Select the individual offer or package. Under Price and quantity choose group calculation, enter base price and units per group, then set the discount for additional identical groups. Example: €300 for the first group with 20% off additional groups gives €540 net for two groups. This offer’s variants and travel costs are applied using their own rules.

Use your own terminology

Open Unit labels under Price and quantity. Enter singular and plural names for the input and, for groups, the billing unit: for example image/images and batch/batches. Empty fields retain default terms. Labels can be translated and never change quantities or price rules.

Explain the card unit

Under Content and presentation, enable “Explain the price unit”. With no custom text, grouped offers show their actual conversion and tiered prices show their calculated scope. Fixed price × quantity does not repeat the quantity in an extra explanation; the input already shows it. Custom text can contain {participants}, {groups}, {group_size} and {quantity}, for example “Each box contains 12 bottles”. Tokens stay unchanged when you rename visible units. Each single offer and package uses its own settings.

Change control labels centrally

Open Settings → General and labels → Quantity control labels to find four text fields. These settings are also available in Free; group conversion, tiered pricing and custom variants require Pro.

Build your catalogue · Pro

Packages and individually selectable components

Build fixed packages and custom combinations without charging groups or extras twice.

Where to find this setting

OfferWeave → Offers → Packages and options

Single offers and packages stay separate

A package uses its own price, quantity, group size, variants and taxes. Settings on an included single offer do not change this calculation. A single booking exclusively uses the single offer’s settings. Changes to package prices or quantities never flow back.

Fixed package

  1. Create a package with included offers. Set its full package price and group rule under Price and quantity.
  2. Under Packages and options select included content. Search helps with larger catalogs.
  3. The assignment describes included content. Individual prices are not charged again. A component’s own model, group size or billing period does not override the package.

Assembled package

  1. Choose an assembled package and its quantity or group calculation basis.
  2. Assign contents. New editor assignments start at €0: explicitly enter the Price inside this package for each selected component.
  3. These component prices belong to the package. Later single-price changes are not synchronized. The same content may have different prices in different packages.
  4. Minimum count controls the number of distinct contents. Minimum price raises a low package base price. The global request condition only blocks submission; it does not increase a price.

Updating older versions

Version 2.13 removes the former shared calculation link. Historical linked fixed-price cards receive their last effective quantity rules once as independent settings; already configured group offers retain their own values. Previously dynamic component prices are stored once inside each package. Thereafter no live price inheritance remains. Related request conditions continue to cover detached single offers.

Back up before updating. Then check single and package bookings with typical quantities, surcharges and taxes. Existing requests retain their saved calculations. Nested packages and self-references remain unsupported.

Shared surcharges, variants and delivery

Maintain named surcharges centrally, assign them to offers and optionally link them to variants.

Where to find this setting

OfferWeave → Surcharges / Offers → Price and quantity / Packages and options

Maintain your own surcharges centrally

  1. Open Surcharges and choose Add surcharge. Enter a clear name such as Setup, Express processing or Materials.
  2. Choose a flat amount, an amount per offer unit, participant or group, a percentage, or an additional customer-entered quantity. Enter the amount in your global currency.
  3. For an additional quantity, define its unit and default. Quantities allow two decimal places, such as 1.25 hours. The amount is the price per such unit.
  4. Save the configuration. A surcharge is only calculated once assigned to an offer. Central price changes affect every assigned offer after saving.

Assign to offers and set conditions

  1. Open the offer under Price and quantity and locate Assigned surcharges.
  2. Select a compatible central surcharge and choose Assign surcharge. Incompatible calculation bases are not offered.
  3. Choose Always, On site only, or a specific variant option. A variant condition needs an existing enabled option group and option.
  4. Save and check the card and selection. Applicable amounts are included in the total and explained by name. Additional quantities appear only when their condition applies.

Use the × next to a surcharge name to remove only its assignment to this offer. Manage surcharges opens the central library. When no further matching surcharges are available, a text notice replaces the empty selector. Fields stack on narrow panels.

Surcharges apply per selected offer line and follow its billing period and tax rate. Percentages use the service base after quantity rules and before promotions. Surcharges are not discounted and do not compound. Packages apply their own surcharges; component surcharges are not added again.

Enable or disable a surcharge centrally. Remove all offer assignments before deleting it. Existing requests and their emails retain the saved names, quantities and amounts. Existing on-site and travel rules remain unchanged; do not assign the same costs again as a new surcharge. Central surcharge management is included in Pro.

Build variants

  1. Enable variants on the offer. For linked components, edit their shared selection package.
  2. Add an option group with an ID and title, such as delivery / “Delivery”.
  3. Create options such as “At the studio” and “At your location”. Assign stable IDs and enter each net surcharge.
  4. Choose whether selection is required and which option is the default. Optional groups also allow no selection.
  5. Add further groups such as Standard or Express processing. Customers select exactly one option per group; several groups can be combined.

The selector shows only the configured option name, such as “At the studio” or “At your location”. Amounts, percentages, calculation bases and “No surcharge” are not appended automatically. The selected surcharge remains included and explained in the card price. Optional groups still offer “No selection”.

Choose the surcharge basis

BasisEffect
Per itemOnce for the offer line
Per quantityMultiplied by the quantity in a quantity-based model
Per participantMultiplied by the total input quantity
Per groupMultiplied by the calculated groups
PercentagePercentage of the calculated service base, excluding other extras

Example: €300 base price, 10% Express and €20 packaging per item produce €350 net. The percentage is not also charged on packaging. For monthly offers, variants apply to the monthly amount. Negative surcharges are not supported; use promotions for discounts.

Delivery and travel costs

A group marked as delivery can link options to the configured travel rules. When an on-site surcharge is represented by a variant, the older delivery surcharge is not charged twice. Still check travel costs separately: unresolved travel costs must remain visibly open.

Linked components use the shared package variants. Maintain a shared extra there once. Promotion discounts affect the eligible service amount; variants and travel/on-site extras are not discounted.

Change “Delivery format” centrally under Settings → General and labels → Quantity control labels. Edit the title of a custom variant group directly on its offer.

Test and maintain

  • Every required group needs a valid selection. Also test an optional group with no option selected.
  • Check quantity 1 and multiple units or groups, including totals in the selection and email.
  • Remove IDs deliberately. Customers must reselect if an older browser selection refers to an option that has been removed.
  • Technical limit: up to 20 groups with 100 options each. Keep the visible selection as short as practical.

Currency, taxes and price display

Set the global currency, tax rates and net/gross display for cards, selections and emails.

Where to find this setting

OfferWeave → Settings → Prices and conditions → Currency / VAT and price display

Settings: Prices and conditions

Open Settings → Prices and conditions to choose the default currency and configure VAT, net/gross display and request conditions. All supported currencies are selectable in Free and Pro. Tax settings are included in both editions.

Every offer card groups the price with its unit. The VAT label sits immediately below, before participant counts, group explanations and other notes. This also applies to promotional prices, variants and the design preview. The net/gross setting still determines the VAT label.

Change the default currency

  1. Under Currency → Default currency, choose the ISO code and name, such as EUR, USD, CHF, GBP or JPY. New and existing installations default to EUR.
  2. Save the change. The symbol and decimal places apply to offer prices, variants, fixed discounts, minimum values, travel costs, previews, new requests and emails.
  3. Review your prices and manually written currency references. Numerical amounts are preserved: 100 EUR becomes 100 USD. No exchange-rate conversion is performed.

Decimal places follow the currency: for example, two for EUR, none for JPY and three for KWD. If an existing amount cannot be represented exactly or exceeds the input limit, the currency remains unchanged. Adjust that amount first. Tax and discount percentages do not change.

One default currency applies to the entire provider catalog. Mixed currencies per card and automatic exchange rates are not included. Saved requests and regenerated emails retain their original currency; legacy requests without a currency field remain EUR. OfferWeave license prices in EUR are independent of this setting. The following price examples use EUR.

Always enter source prices as net amounts

Base prices, variants, travel costs and fixed promotion discounts are maintained as net values. The display setting determines whether cards emphasise net or gross prices. Switching the display does not change stored base prices. Selection totals and email quote blocks break down tax and the total amount.

  1. Enable taxes under Settings and enter a default rate, such as 19%.
  2. Choose the preferred net or gross display and check the configured customer audience.
  3. For a different rate, open the individual offer. An empty tax field inherits the default; an explicit 0% means zero tax.
  4. Check cards, detail selection and a saved test request. B2C or mixed audiences require complete tax settings and emphasise gross pricing accordingly.

Example and rounding

Two print layouts at €120 produce €240 net. At 19%, tax is €45.60 and gross is €285.60. Discounts are applied before tax. Tax is rounded to the selected currency’s smallest unit per line and billing period; totals add these rounded values. For monthly services, the rounded monthly value is summed over the term.

A package is one line with its own tax rate. Different component rates are not applied separately within that package. Variants and ancillary costs on that line also use its rate.

Important limits

  • Open prices and travel costs are not zero prices. Check the incomplete-total notice.
  • OfferWeave does not determine tax from customer country, VAT ID or reverse-charge validation.
  • This setting is not an invoicing system and does not determine your tax treatment.
  • Earlier requests retain their saved amounts and rates; later changes affect new calculations.

When a selection can be submitted

Combine minimum value and distinct-offer count without changing prices.

Where to find this setting

OfferWeave → Settings → Prices and conditions → Request conditions

Configure a condition

  1. Enable request conditions. Choose whether they apply to every selection or are triggered by specified offers.
  2. Enter a minimum net value and/or minimum number of distinct offers. Zero disables that individual condition.
  3. Choose “All conditions” for AND or “At least one” for OR.
  4. Review the automatically generated customer notice. Save and test both an invalid and a valid selection.

Worked examples

GoalSettingResult
At least €349 regardless of countMinimum €349, count 0A single €349 offer qualifies
At least two distinct offersMinimum 0, count 2Twice the quantity of the same offer is not enough
At least €349 and two offers€349, count 2, all conditionsBoth requirements must be met
€349 or two offers€349, count 2, at least oneEither requirement qualifies

“At least €349” includes exactly €349. For a strictly higher amount, choose a higher cent threshold such as €349.01. The check uses known net values after discounts, including monthly services over their term.

Scope and components

A list of specified offers determines when the rule is triggered. Once one is included, the entire selection value is checked, not just the marked offers. Selected components can also trigger a rule. Distinct components count individually; increasing the quantity of the same ID does not create another distinct offer.

Unknown price portions add nothing to the known minimum value. Customers can collect and edit smaller selections; only submission is blocked. A package minimum price is different: it raises the calculated price.

Display on your website · Free + Pro

Pages and shortcodes

Place quantity controls, catalogues, single cards, detail selection, request forms and promotion banners precisely.

Where to find this setting

Availability in Free and Pro

Offers with and without JavaScript

PHP renders cards, images, prices and detail links into the original page source. You do not need additional HTML copies of the offer cards. The design editor uses the same output as the website.

  1. With JavaScript, quantities, options and prices update without a full page navigation.
  2. Without JavaScript, change the inputs and select “Update price”. WordPress calculates the new price and reloads the page with your values.
  3. Adding, editing and removing selected items and submitting the request form also work without JavaScript. A request is saved only when the form is submitted.
  4. Separately positioned inputs remain connected to their catalog. Mixed pricing models keep individual quantities separate; shared delivery applies to the offers configured for it.

For selection across pages, OfferWeave uses a cookie with a random identifier. The identifier lasts two hours, and the temporary selection is held in the WordPress cache. Contact details are not placed in the cookie or URL. Submitted requests continue to use the configured retention period.

An optionally enabled hCaptcha or Cloudflare Turnstile requires JavaScript. This check is not bypassed. Without JavaScript, the visitor must enable it to submit the form or contact the provider directly.

OfferWeave sends private no-store responses for selection pages. Configure page and CDN caches so pages with OfferWeave shortcodes and responses for the offerweave_selection_* cookie are not shared between visitors. Clear existing page caches after updating.

Replacing old shortcodes

From 2.35.4, cqb_builder, cqb_catalog, cqb_request, cqb_phishing, cqb_workshops, cqb_modules and rq_request are no longer registered. Replace them with offerweave, offerweave_catalog, offerweave_request or a catalogue with the appropriate category ID. Existing offerweave shortcodes remain unchanged; separate inputs and banners require Pro. The old convati-quote/v1 REST address is removed; custom integrations use offerweave/v1. Offers, settings and requests are still migrated.

Selection messages

Add confirmations appear once and disappear after eight seconds when JavaScript is enabled. Close a message immediately with ×; hovering or focusing it pauses the timer. Without JavaScript, it remains readable until the next page load.

Opening a page can restore a previous browser selection. A yellow notice means that items which are no longer available could not be restored. Review the selection. This warning and submission confirmations with a reference number do not disappear on a timer. You can dismiss them; a new page load or action can replace them with new feedback. Background refreshes do not remove them.

Global styling, individual overrides and useful checks on narrow pages.

Where to find this setting

OfferWeave → Design

Global or one card only

  1. Open Design and choose “All offers – global design” for the shared baseline.
  2. Set card layout, colours, font sizes, borders, radius and spacing. The preview shows your draft.
  3. Select an individual offer when only that card should differ. Enable overrides only for the values you need.
  4. Disable an override to inherit its global value again. Saving publishes the design; previewing alone does not change your website.
Individual design values take precedence over global values. Changing an image assignment does not change card colors. Leave “Customize” off to inherit a global value; enable it only for a deliberate difference. Layout and icon edits also update the preview markup immediately.

You can open several settings sections at once. Colors, Images and the other sections stay open when you change values, toggle “Customize”, reset or save. When switching between offers or banners, the designer remembers the open sections for each scope during the current editor session. Reloading the page returns to the initial view.

Set columns globally or per category

  1. Open OfferWeave → Design. Under “All offers – global design” → Layout, set the desktop, tablet and phone columns.
  2. Choose “Category: Photography – layout”, or your offer category, as the scope. Search by category name or ID.
  3. Enable “Customize” for each screen size that needs its own value. For example, set desktop columns to 2. Unchecked values continue to inherit the global layout.
  4. Check the single example card on the right at its actual catalog width. Desktop, tablet and phone use the same inheritance as the website. Save the configuration.
  5. Uncheck an individual override or select “Remove all overrides” to restore the global layout. Other categories remain unchanged.
The order is explicit: a category value takes precedence over the global value, separately for each screen size. Later global changes only affect inherited values. Allowed ranges are 1–4 desktop columns, 1–3 tablet columns and 1–2 phone columns. Fewer offers reduce the actual column count accordingly.

Category columns are part of the Pro designer. They apply to category catalogs and category tabs in the configurator. When an unfiltered catalog contains several categories and at least one category override, each category has its own grid, in order of first appearance. Offer order within each category is preserved. Shared quantity and variant fields remain shared. Without category overrides, the existing common grid is retained.

Individual offers and [offerweave_add] remain single full-width blocks. Category overrides do not alter card colors or prices. Free uses its global base layout and preserves saved Pro values. Settings for unused category IDs remain available if the category is reused later.

Section background per category or individual offer

  1. Open OfferWeave → Design. Under “All offers – global design” → Layout, set the shared section background.
  2. Choose “Category: Photography – layout” or your category. Enable Customize for Section background and choose a color. This is the area around and between cards.
  3. To show the website behind the block, customize Transparent section background and enable transparency. Active transparency takes precedence over the color.
  4. For an individual offer shortcode, choose the offer as the design scope instead. Customize its section background or transparency under Layout. Select “Single offer at full width” in the preview to check this surface. Catalog width shows the category background.
  5. Save the configuration. Fields without an override follow the global value; removing an override restores inheritance.
[offerweave_catalog category="photo"] uses the category background. [offerweave_offer id="photo1"] uses the offer background. An explicit offer/id filter in a catalog also uses the individual offer. The individual view does not inherit the category background. Card background under Colors is separate.

In an all-category catalog, each separate category grid has its own background. The shared outer area and shared controls keep the global background; transparent grids reveal this shared area. Category tabs change the background with the active category. The [offerweave_add] selection block keeps its independent global design. These settings belong to the Pro designer; saved values are preserved when switching to Free.

Style selection blocks independently and choose their content

Price left, content right

Add and position images

Use one media-library image or direct image URL per offer; full image styling is a Pro feature.

Where to find this setting

OfferWeave → Offers → Content and appearance → Image

Assign an image

  1. Open the offer or its image area in the designer.
  2. Select a WordPress media-library image or upload one there. Alternatively, enter a direct image URL.
  3. Provide meaningful alt text. An image used only for decoration can explicitly be marked decorative.
  4. Save and check the card on your website. Remove the assignment to show the offer without an image.

JPEG, PNG, GIF, WebP, AVIF and SVG are supported. Use SVGs as offer images and key-fact icons. New SVG uploads require WordPress to allow the file type, for example through an SVG extension with sanitization. OfferWeave uses the standard WordPress upload and does not change that permission. Existing SVGs can be selected from the media library even without generated thumbnails. A media image can inherit its media-library alt text; without a suitable value the offer name may be used as a fallback. Check the text deliberately instead of always relying on the fallback.

Style position and size

The Pro designer controls image position, width/height, fit, border, radius and spacing. Choose the position first, then a suitable crop. A logo often needs to be shown in full, while a photo can be cropped. These settings change display, not the original media-library file.

  • Check that cropping preserves important image content.
  • A transparent image blends into the card background.
  • Removing an assignment does not delete the file from WordPress.
  • All cards can be used without images for a quieter comparison layout.

External images and migration

External image URLs load files from that provider in the visitor’s browser. Prefer your own media files and check their usage rights. Configuration exports contain references, not image files. When moving a website, move the files too and reassign media-library references if necessary.

Promotions, discounted prices and banners

Schedule discounts, select affected offers and style banners independently of the catalogue.

Where to find this setting

OfferWeave → Promotions; Design → Promotion banner

Create a promotion

  1. Create a draft promotion with a unique ID, internal name and the required banner text. Saving alone does not start it.
  2. Choose a percentage discount or fixed net discount. Enter valid start and end dates. Enabled promotions require both boundaries.
  3. Select affected offers. Use search, category filters and the selected-offers filter instead of scanning a long list.
  4. Enable banner display if required, then click “Start promotion”. This command saves the promotion and pending configuration changes. A future start date produces the Scheduled status.

Date boundaries use the WordPress timezone. The start applies from the beginning of the day; the end includes the entire end date. Blank date fields are permitted only while the promotion is disabled. Overlapping enabled promotions on the same offer are rejected when saving.

Discount and price comparison

Discounts apply to the eligible service amount. Variants, on-site and travel extras remain additional. For fixed packages, select the package itself as affected. A component discount applies to individual booking and is not deducted again within a package.

Cards compare regular and discounted prices for the same scope and net/gross display. Use the design editor to style the new price colour and size and the struck-through price. Also check multiple groups or quantities and the selection breakdown.

Insert a banner where required

  2. Open Design and select the global promotion-banner scope or a specific promotion.
  3. Style background, text, border, radius and spacing. Individual values can be reset to the global style.
  4. Check the banner at narrow widths, with long text and at the beginning/end of its validity period.
OfferWeave does not maintain a historical lowest-selling-price archive. A technically correct struck-through price therefore does not automatically confirm compliance of a specific price advertisement.

Remove an assignment to a missing offer

If a saved promotion refers to an offer that has since been removed, Pro shows a selected Missing offer row with its previous ID. This row remains visible even when search and category filters are applied.

  1. Open Special offers and select the affected promotion.
  2. Check the displayed ID, then clear the checkbox directly beside Missing offer. This removes only that assignment; you do not need to delete the promotion.
  3. Review the remaining offer selection and save the changes. At least one existing offer must still be assigned before the promotion can start.
Opening, filtering or closing the view does not remove saved assignments. Saved promotion data also remains intact when a Free installation edits its normal offers; explicit repair takes place in Pro.

Fields for your workflow

Set up SMTP and diagnose errors

Send your designed OfferWeave emails through your own mail provider.

Where to find this setting

OfferWeave → Email → Delivery and sender / Mail transport

Two transport options

Without own SMTP, OfferWeave uses WordPress mail. An existing SMTP plugin can handle that transport. The integrated Pro transport applies only to OfferWeave emails. It does not change your customer email design: the same styled message is sent through the selected transport.

Enter the complete credentials

  1. First enter a valid sender email in Delivery and sender. This is a separate field and is not automatically copied from the SMTP username.
  2. Enable “Use own SMTP delivery” and open the credentials area.
  3. Enter a hostname without https:// or a path, such as mail.example.invalid. Use your provider’s real settings.
  4. Choose its port and encryption. Common pairs are 587 with STARTTLS or 465 with SMTPS; they must match.
  5. If authentication is required, enable it and enter username and password. Save.
  6. Check preview, then deliberately send yourself a test email.

What “Password stored” means

After saving, the password field is blank; a notice confirms an existing value. Leaving it blank preserves that value. Enter a new password to replace it; use the explicit delete option to remove it. The stored password is not included in configuration exports or preview payloads.

Stored-password encryption depends on your WordPress environment. After migration or changed WordPress security keys, you may need to enter it again. Do not copy credentials into screenshots, error reports or your website.

Import, export and site migration

Back up configuration, import drafts and handle images and requests separately.

Where to find this setting

OfferWeave → Import & Export

Export configuration

  1. Save the intended configuration first.
  2. Open Import & Export and download the JSON export.
  3. Store it securely with a version and date. It can contain provider information and email addresses.

A configuration export is not a full WordPress backup. It includes neither saved requests nor image files. SMTP passwords and secret CAPTCHA values are excluded. The export also resets notification recipient, sender/reply addresses, request/privacy URLs and CAPTCHA integration, and disables customer emails. Explicitly configure these on the destination system again.

An import replaces the draft configuration. Values in the file take precedence over defaults, including zero, disabled options and empty fields. Missing fields in older files receive neutral defaults; old translations and removed offers from the previous configuration are not merged in. Only saving publishes the import. Private preset migrations do not automatically replace an imported configuration; applying that preset remains an explicit action.

On the same WordPress installation, existing SMTP and CAPTCHA secrets are retained if the imported file supplies no replacements. They are not part of the portable export. Check the connection after importing; enabling SMTP is independent of email design.

Before loading an import, confirm in the OfferWeave dialog that it may replace the current draft. Cancel preserves the draft. Import and export errors also appear as OfferWeave notices.

Review and apply an import

  1. Back up the current state before importing.
  2. Select the JSON file. A successful import first loads its content into the editor.
  3. Review offers, prices, tax/form settings, URLs, image assignments and email transport.
  4. Save only after checking. Import replaces configuration; it does not automatically merge two catalogues. Saved requests remain.
Importing does not unlock Pro features in Free. Package, form-field or template dependencies can prevent changes. A failed import does not change the saved state. Imports are limited to 512 KiB.

Additional migration checks

  • Move the WordPress database and media using an appropriate backup/migration process.
  • Update detail/privacy URLs for the target domain and reassign differing media IDs.
  • Re-enter the SMTP password if WordPress security keys changed.
  • Check CAPTCHA keys against the target hostname.
  • Test a complete enquiry and both language versions before using the new site publicly.

Updates, backups and retention

Update the plugin and deliberately control how long requests are stored.

Where to find this setting

WordPress → Plugins; OfferWeave → Settings → Protection and data

Settings: Protection and data

Open Settings → Protection and data. CAPTCHA, request limits, retention and uninstall behaviour.

Perform an update

  1. Back up the WordPress database, plugin files and media. Also export OfferWeave configuration.
  2. Install the new ZIP for the same edition or use its intended update channel.
  3. Check the version after updating. Clear page/optimisation caches if the old interface is still loaded.
  4. Check at least one single card, a complex package, the selection and email preview. Also submit a complete enquiry on a staging installation.

A normal update does not reset existing configuration or requests. Custom changes are preserved; new default wording is not blindly written over your text. Read release notes for targeted migrations.

Retention and deletion

The retention period in days controls automatic deletion of old requests. Zero disables automatic expiry; up to 3650 days can be configured. Cleanup runs through WordPress Cron and may be delayed on low-traffic websites. Processing status does not exempt a request from retention.

Choose a period appropriate for your obligations and workflow. The plugin does not restore deleted requests from a recycle bin. Configuration exports do not contain requests.

Deactivate and uninstall

Deactivation stops the plugin while preserving stored data. A separate setting controls data deletion during deliberate uninstallation; review it before removal. While another OfferWeave edition is active, its shared data is protected when removing an inactive edition.

Expired service access is not an uninstall and does not delete data. Test switching between Free and Pro on a copy first because Free does not publicly provide complex offers.
